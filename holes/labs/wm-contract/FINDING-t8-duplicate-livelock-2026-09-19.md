## 1. What the detector measures

T8 is a **repetition detector**, not a causal deduplication writer. It groups findings by `[failure-kind-or-repair-class, target, failed-commit]`, excludes resolved/superseded ids supplied by the snapshot, requires a target or failed commit, and emits a witness above two findings. Current code additionally requires the newest dated finding to be at most 24 hours old; an entirely undatable group still fires. The age constraint is on the newest member, not on every member. Evaluation is at opportunity/start or under the force option. Sources: `src/futon2/aif/tripwire.clj:318-404`, snapshot and closed-id construction `:896-912`; phase emission invokes observation in `src/futon2/aif/full_loop_runner.clj:270`.

The observed signature in all four specimens is `[:build-failed, repair-ea1-504ad8630070adf67604aab739c0c0184b5ccf632f552ec6d2b55fac7ad71c87--attempt-001-feature-card-missing-or-invalid, nil]`. It does not hash the error, job id, payload, attempt id or selected code. Thus T8 proves repeated recorded failures against one target, not that all failures have one low-level cause. In these specimens the retained job records independently support the same dispatch-failure class (tables below).

## 3. Why reporting made the queue grow

The incident-era chain is: opportunity/start → T8 witness → halt writes a trip report and throws typed `:tripwire-tripped` → outer initialization catch creates a fresh `initialization-<UUID>` → `record-system-failure!` writes a new open machine-failure obligation. Current source retaining those boundaries: `tripwire.clj:993-1020`; `full_loop_runner.clj:4784-4821`; `repair_obligation.clj:446-480`. The four retained exception payloads match this shape. Their trip reports say `:trip/action :record`; that report action does not negate the separately recorded thrown exception.

History matters: `a8ac1615` (2026-09-18 23:58:23 UTC) introduced witness shutdown with unresolved/discriminator filtering. Its `livelock-violations` has no age window: the first two specimens at 00:00 and 00:54 replayed the three September 15 findings as a current halt. `3fa116ff` (01:11:00) introduced the newest-member age limit, after D at 01:09; the later two witnesses legitimately satisfy that new recency condition. `8f7799b7` (01:37:44) added pre-selection deferral for repair-covered witnesses, after all four specimens. `a03ae7b0` (14:16:27) made witness halts opt-in. Sources: these commits' tripwire diffs/history and current `tripwire.clj:953-1069,1132-1142`.

Consequently **the historical four-finding loop is not proof that default current code still mints an initialization finding for every T8 observation**. Current repair-covered pre-selection witnesses are durably deferred without a second obligation; ordinary note mode records without throwing. These mitigations keep detection, but do not provide general durable causal idempotency across writers (`tripwire.clj:1032-1085,1132-1142`). T8 does not recursively count these four top-level nil-target/nil-commit findings itself, because of its discriminator filter (`:375-378`).

## 5. Proposed fix shape only — requires separate authorization

1. Separate **occurrence identity**, **repetition signature**, and **observation event**. For an actual failed action, propose an authority-qualified external attempt plus stable origin/job/event identity and typed originating failure kind. Propagate that identity and the original finding through containment layers. Do not key merely by local attempt ordinal or target: independent attempts/jobs really are distinct events (A–D; runner comments at :4494-4500).
2. At the durable writer, atomically publish/reuse a finding by that occurrence id, retaining the original opened-at and immutable payload. A retry observation appends evidence referencing the existing finding; it does not invent another open finding. A conflicting semantic payload under the same occurrence id should refuse. Preserve the existing publication lock/CREATE_NEW/conflict protections (repair_obligation.clj:340-388), extending identity rather than weakening publication.
3. For T8 itself, use a durable witness identity such as wire id + detector version + canonical signature + **sorted source finding ids**. Exclude report UUID, rendering order, observed-at and derived age. A/B/C reports then share one observation identity; addition of D is a new witness version linked to the same continuing incident, not an unexplained new repair target. Current deferral already recognizes that named source obligations exist; extend that evidence/obligation distinction rather than turning the detector off (tripwire.clj:1032-1085).
4. Distinct failed retries must remain countable by T8. If an authorized retry/supersession policy consolidates them under one outstanding obligation, retain each attempt event and adapt the detector to count those events. Blindly deduplicating by T8's broad signature would erase its evidence and effectively disable it. A normalized payload hash may detect exact content repetition but cannot establish causal identity by itself; these specimens contain both identical witness pairs and an expanded witness set (tables).
5. Disposition of the existing four machine-failure findings needs an explicitly authorized transition with links to original reports/source obligations. Do not delete them, claim a code repair happened, or call the incomplete-recoverable-only supersede! on them. Proposed adversarial controls: same occurrence through inner and outer catch yields one finding; parallel identical publication yields one; another job/attempt remains distinct; reordered or aged witness does not remint; adding D preserves new repetition evidence; three unresolved distinct events still trip T8; resolved/authorized successor states are handled explicitly. These are proposed tests, not executed results (identity/publication and supersession sources above).
