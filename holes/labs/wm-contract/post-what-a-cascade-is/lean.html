Codex-6 delivered a first version on 30 September: mathlib4/DarkTower/WarMachine/CascadeSpec.lean (commit 5762bc703e, builds, no sorry). Claude-1 read it. What it establishes and where it still falls short:

In the moduleWhat it saysAssessment
CascadeA nonempty finite set of units with precedes and overlap relations. Building one requires proofs that every label is a library pattern, every edge joins two of its units, and precedes has no cycle.Sound. A cascade with a cycle, or with a label outside the library, fails to typecheck; both failing controls are in the file.
GraphEdge.authoredDirectionDirection is a recorded field of a graph edge, or absent. It is never derived from names.Sound as a definition. Not yet enforced on retractions (below).
PolicySet, constructA policy set has a private constructor; the only way to obtain one is construct reading graph params, which deduplicates the reading’s cascades together with the graph retractions of the reading’s usable seeds.Partly. See the first gap.
Five theoremsEvery member is a valid cascade; members are pairwise distinct; every member contains a pattern the reading cites; an empty reading gives an empty policy set; the number of members is at most the number of reading cascades plus k.Proved. The last one makes k visible as the bound on how many retractions a target can have.

Gap 1: the free list has moved, not gone. In this version a Reading carries its own list of cascades as a field, constrained only to mention a cited pattern. Anyone can therefore build a reading whose cascade list is whatever they choose, and construct will accept it. That is the old menu argument one level down. The correction, requested from Codex-6: a reading is its fragments only, and its cascades are computed from them by a function defined in Lean that mirrors the code.

Gap 2: retraction direction is not constrained. The contract a retraction must meet says its edges come from the graph, but not that an arrow must follow an authored direction. The alphabetical arrows in the drawings below would satisfy it. The correction makes an implementation that directs edges by name order fail the contract, with that failure shown in the file.

Gap 3: one control tests the wrong thing. The control meant to show that a hand-written list is refused fails because a list is not a structure, which would be true whatever the constructor’s visibility. The replacement goes in a second file and tries the constructor directly.

The retraction computation itself (a cheapest tree joining the seeds) is not defined in Lean. It enters as a named function with stated properties, so it is an input declared as supplied from outside, with its source being pattern_retraction.clj.
