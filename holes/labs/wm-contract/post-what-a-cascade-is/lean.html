In the moduleWhat it says
ReadingA list of fragments, each a list of citations of library patterns. It has no other field: there is nowhere to put a list of cascades.
readingCascadesA function from a reading to its cascades, in two modes. Units are citations. Every unit of one cited fragment precedes every unit of the next cited fragment. In alternatives mode one citation is chosen per fragment, in every combination; in overlap mode all citations are kept and those in the same fragment overlap.
CascadeA nonempty finite set of units with precedes and overlap relations. Building one requires proofs that labels are library patterns, edges join its own units, and precedes only runs forward, so it has no cycle.
GraphEdge.authoredDirectionDirection is a recorded field of a graph edge, or absent.
RetractionSpecThe contract the retraction computation must meet: every retraction contains every seed it was given; its labels are library patterns; each precedes edge follows a graph edge authored in exactly that direction; each overlap comes from a graph edge with no authored direction; no seeds gives no retractions; at most k are returned.
PolicySet, constructThe constructor of a policy set is private. The only way to obtain one is construct reading graph params: the reading’s cascades together with the retractions of its usable seeds, deduplicated.

Proved: every member is a valid cascade; members are pairwise distinct; every member contains a pattern the reading cites; an empty reading gives an empty policy set; the number of members is at most the number of reading cascades plus k.

Checked against the code on one fixture: a first fragment citing two patterns and a second citing one. Lean and analysis->cascades both give two alternatives of two units and one ordering edge each, and one overlap cascade of three units, two ordering edges and one overlap.

Controls that fail as they should, in the second file: calling the policy-set constructor by name; building a policy set with structure notation; giving a reading a list of cascades. In the main file: proving that an edge with no authored direction justifies an arrow.

Where the Lean and the code still differ, found on reading and sent back to Codex-6:

  • The construction takes one reading mode. The code forms the policy set from both modes together.
  • The retraction contract requires every undirected graph edge between two patterns of a retraction to appear as an overlap. The code keeps only the edges of the tree it found, so the real computation may not satisfy the contract as written.

What the Lean does not say. The retraction computation itself is not defined; it enters as a named function with the contract above, sourced to pattern_retraction.clj. Nothing requires a policy set to have more than one member; a run whose policy sets are degenerate is caught by the run-facts check and the alert, not by this module. And nothing says the fragments are the operator’s own words.
