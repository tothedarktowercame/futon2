In the moduleWhat it says
ReadingA list of fragments, each a list of citations of library patterns. It has no other field: there is nowhere to put a list of cascades.
readingCascadesA function from a reading to its cascades, in two modes, both of which go into the policy set. Units are citations. Every unit of one cited fragment precedes every unit of the next cited fragment. In alternatives mode one citation is chosen per fragment, in every combination; in overlap mode all citations are kept and those in the same fragment overlap.
CascadeA nonempty finite set of units with precedes and overlap relations. Building one requires proofs that labels are library patterns, edges join its own units, and precedes only runs forward, so it has no cycle.
GraphEdge.authoredDirectionDirection is a recorded field of a graph edge, or absent.
RetractionSpecThe contract the retraction computation must meet: every retraction contains every seed it was given; its labels are library patterns; each precedes edge follows a graph edge authored in exactly that direction; each overlap comes from a graph edge with no authored direction; no seeds gives no retractions; at most k are returned.
PolicySet, constructThe constructor of a policy set is private. The only way to obtain one is construct reading graph params: the reading’s cascades together with the retractions of its usable seeds, deduplicated.

Proved: every member is a valid cascade; members are pairwise distinct; every member contains a pattern the reading cites; an empty reading gives an empty policy set; the number of members is at most the number of alternatives cascades plus the number of overlap cascades plus k.

Checked against the code on one fixture: a first fragment citing two patterns and a second citing one. Lean and analysis->cascades both give two alternatives of two units and one ordering edge each, and one overlap cascade of three units, two ordering edges and one overlap.

Controls that fail as they should, in the second file: calling the policy-set constructor by name; building a policy set with structure notation; giving a reading a list of cascades. In the main file: proving that an edge with no authored direction justifies an arrow.

Two differences from the code, found on reading and since corrected (65f9cb58e3): the construction now uses both reading modes together, as the code does; and the contract no longer requires every undirected graph edge inside a retraction to appear, since the code emits only the edges of the tree it found. A further theorem states that with k = 0 the policy set is exactly the deduplicated reading cascades.

A defect found by trying a real example (30 September), and its correction. Asked to write the M-distributed-proofreaders policy set as Lean terms, Codex-6 stopped: the three retractions could not be expressed. The definition gave every unit a fragment number and a position within the fragment, allowed an overlap only between units of the same fragment, and ordered arrows by fragment. Those are properties of a cascade read from a text. A retraction’s connector patterns were never cited, so they have no fragment, and its overlaps are graph edges. Filling the fields would have meant inventing numbers. In 0fbd20ddcd the definition is changed: a unit has an identity and a library pattern, with reading provenance optional; an overlap is any pair of distinct units; and the ordering carries an explicit rank that every arrow must increase, which is what rules out cycles. What is particular to reading cascades (every unit has provenance; two units overlap exactly when they share a fragment) is now proved about the reading function and is no longer demanded of every cascade. The tables above describe the definition before this change; the rows for Cascade and readingCascades should be read with it.

Duplicates are now removed as the code removes them (ebacba1166): the construction keeps the first cascade of each structural identity (patterns and relations, ignoring provenance and rank), with reading cascades ahead of retractions. It is proved that the result contains only cascades from the source list, is no longer than it, and has pairwise distinct structural identities.

Still open, by Codex-6’s own account. The fixture check is proved for the unchecked form of the reading function, not for the checked one the construction uses, and the fixture’s policy-set count is not yet proved. The real example has not yet been regenerated against the corrected definition. Both are with Codex-6.

What the Lean does not say. The retraction computation itself is not defined; it enters as a named function with the contract above, sourced to pattern_retraction.clj. Nothing requires a policy set to have more than one member; a run whose policy sets are degenerate is caught by the run-facts check and the alert, not by this module. And nothing says the fragments are the operator’s own words.
