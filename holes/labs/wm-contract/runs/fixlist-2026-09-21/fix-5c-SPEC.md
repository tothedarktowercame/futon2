## 2. Smallest interpreter contract

Use a new **preselection** envelope. Do not loosen the attempt identity checks in
`interpretation-evidence`, manufacture a cohort/attempt, or reuse the
post-selection `interpretation-job/run!` as though selection had already occurred.

Request schema `:wm/preselection-interpretation-request-v1`:

```edn
{:schema :wm/preselection-interpretation-request-v1
 :request-id "immutable UUID"
 :created-at "UTC instant"
 :target {:id "mission id" :want-id "content-addressed hole/span id"
          :source-id "captured source id" :citation {:source "..." :lines [150 150] :quote "exact bytes"}
          :closure-observation {:class :C4 :repo "futon2" :path "..." :decl "..."}
          :activation {:status :unestablished :source-citations []}}
 :sources [{:id "..." :path "/original/path" :file "safe-companion-name"
            :revision "..." :sha256 "..."}]
 :proposals [{:proposal-id "..." :pattern "qualified/id" :source-id "..."
              :retrieval {:retriever "..." :rank 5 :version "..."}}]
 :policy {:response-schema :wm/preselection-interpretation-v1
          :max-patterns 4 :max-output-bytes 32768
          :allow-genesis? false :allow-execution? false}}
```

Numbers above illustrate **caller-declared** bounds; the implementation must
require them, not silently adopt this example. Request digest covers sources,
exact want, proposals and policy. Same target with changed bytes is a new request.
Only the selected proposal subset needs adjudication in one bounded request;
retain the unrequested remainder and selection rule. Never call it an exhaustive
interpretation of all 48 proposals. Rank can schedule work, not confer admission.

Response `:wm/preselection-interpretation-v1` contains:

* `:request-id`, `:request-sha256`, `:response-sha256`, and source manifests;
* `:attribution` with actor identity, method (`:hand-simulated` or `:model-job`),
  authored-at, and for jobs provider/model identifier, job id, prompt digest,
  final-output digest and dispatch/completion timestamps;
* per requested proposal `:judgments` (`:applicable`, `:inapplicable`,
  `:insufficient-evidence`), reasons and exact mission/pattern citations;
* a token registry, the interpretation map, per-pattern receipts (reading,
  scope-limit, observation-limit, source pin, citations, author), and typed gaps;
* overall `:status :interpreted|:partial|:refused`. Partial process readings can
  coexist with `:no-supported-order` for the real want. A separate constructor
  outcome records whether any actual mission candidate was produced.

A response is **attributed** when it is byte-bound to the actual actor/job and
request, not because the model typed `:by "codex-12"`. The host seals attribution
from dispatch metadata after retaining the returned bytes. In hand-simulation
mode, record the human/agent author and explicit mode, never invent a job/model
id. Unknown model metadata is a typed absence; that envelope cannot claim a
fully identified model experiment. Keep validator identity/version separately
from interpretation authorship.

Validator responsibilities:

1. Reuse the source-manifest, digest, exact-span/quote and immutable companion
   checks implemented in `interpretation-evidence`. `sources!`/`citation!` are
   private; `validate-sources!` first validates an attempt-shaped record. Extract
   shared low-level checks without weakening that existing entry point, then
   add a distinct preselection validator. Do not call its attempt validator with
   a fabricated identity.
2. Add closed-shape request/response validation, request-digest binding, host
   attribution sealing, byte/pattern limits, and exact proposal coverage. Check
   pattern identity against the captured proposal/source; a source-backed
   judgment still is not a mechanical proof of applicability.
3. Accept only constructor-compatible needs/forbids sets and add-only produces.
   Refuse undeclared token ids, arbitrary Boolean guards, delete effects, or
   unsupported theta fields; never drop fields while adapting.
4. Require readings and both limits, with exact source citations. The validator
   verifies attribution, citations and representation. It **cannot prove** the
   reading or intended effect follows from the prose. That remains an explicit
   judgment subject to review and later outcome evidence.
5. Observe initial token values independently through C3–C6 at pinned commits;
   interpreter-reported truth values are not observations. Unknowns remain
   unknown. Fix-5a's `:observation-required` is a request for evidence, not a
   permanent impossibility verdict or permission to assign false.
6. Produce a pure adapter view: `:interpretations` with guard/produces only,
   separate `:interpretation-receipts`, `:observation`, and exact real `:want`.
   Keep the token registry digest and interpreter receipt reference alongside
   it. Construction is downstream, not evidence validating its own premise.

Typed refusal/gap kinds: `:source-unavailable`, `:source-digest-mismatch`,
`:citation-text-mismatch`, `:request-mismatch`, `:attribution-unbound`,
`:unjudged-proposal`, `:response-over-budget`, `:no-applicable-pattern`,
`:unsupported-guard`, `:unsupported-effect`, `:unlocated-token`,
`:token-meaning-mismatch`, `:observation-required`, `:unproduced-need`,
`:activation-unestablished`. Transport timeout/unavailable are distinct from
semantic refusal. Execution activation does not prevent recording a planning
interpretation; it prevents using that interpretation as execution authority.

## 3. Token identity prevents accidental composition

Each token has an immutable semantic definition:

```edn
{:meaning "the specific gap-report path exists"
 :scope {:target "M-a-wmc-scaling" :want-source-sha256 "..."}
 :predicate {:class :C3 :repo "futon2" :path ".../MEASUREMENT-HOLES.edn"}
 :observation-limit "presence only; no assertion about content adequacy"}
```

Compute its canonical `interpretation-evidence/value-digest`; the machine token
is a reader-safe keyword such as `:token/h<digest>` (never a keyword starting
with a hex digit). Needs and produces refer to that exact token registry entry.
A friendly alias like `:holes-written` is display metadata; it is not the join
key. The probe uses readable aliases solely to make the diagnostic inspectable;
it does not implement this proposed inter-request identity rule.

Initial observations add their actual resolved commit, timestamp and check
receipt separately. Future output locators carry an explicit binding obligation
`:revision-role :produced-commit`; they become executable C3/C4 locator maps only
when a real result commit is supplied. Never present the unresolved template as
a completed observation or use tomorrow's mutable HEAD as today's evidence.
Token identity pins the proposition; observation revisions identify when it was
checked. Any change of target, path, declaration, meaning or observation limit
mints a new token. Cross-target unification needs an explicit reviewed mapping;
matching English labels or matching basenames is insufficient.

A locator makes the proposition observable, not true or semantically justified.
In particular C3 on an empty/wrong report would still observe path presence.
For richer claims, specify a real content-check/validation witness with its own
authority in a later slice; do not rename path presence as benchmark success.
