## Why this is not U39/U40

U39 and U40 **project** a rationale out of trace records afterwards, and say so
(`u39_selection_retrospective.bb:14-15`, "no new logging of what is already
logged"). RE4 writes it in the act that persists the decision. The practical
difference is `:rationale/contract-sha`: RE3's contract-pin ledger row is a
`:typed-absence` because *no file in the run store carries the contract
authority sha* — a projection cannot add one after the fact. Every record in
`store/` carries `11c2e44affa167bf85b0a2d7c29d8705f89a8d08`.

## Where a live tick writes

`futon2.aif.selection-rationale/default-store-dir` = `data/wm-rationale/`,
beside `data/wm-trace/`, one file per persisted decision named by the tick's own
`:run/id`. `data/` is untracked (`.gitignore:49`); a run-store slice under
`runs/<run-id>/` is assembled from there exactly as `wm-trace-s5.edn` was
assembled from `data/wm-trace/`. That assembly is RE5's act. **The rationale
content is not reconstructed at assembly time** — it is computed once, at the
decision, from the record that was just written.

When a caller redirects the trace (tests, replays), the rationale follows it to
`<trace-dir>/rationale/`. `rationale-dir` is not a switch on *whether* to
write: both arms write.

## The store

`store/` — four rationale records, one per recorded decision of run
`2026-09-01-s5` (the run RE3's ledger rows are deposited against). Emitted from
the recorded records by `selection-rationale/emit!`, the same function the seam
calls, with the recorded `:timestamp` preserved as `:rationale/at`.

`negative-control-store/` — four **typed absences**, one per illegible-decision
shape. This is the acceptance's negative control: a decision path that fails to
produce a rationale leaves a record saying *why*, not an absent file. The first
keeps run `4e35e740…`'s own id on purpose — the absence is about that decision.

## What the records say about the s5 run

All four are `:recorded :selected` over 145 candidates with 4 admission-stage
refusals (`:mission-absent-from-capability-graph`).

The chosen mission is **not** the controller head on any of them — the R14
strategic selector replaces the controller's choice
(`war_machine.clj:6362-6364`) — so each record carries a `:runner-up` block
naming the head and the G-core margin (0.1469 on all four).

`:controller-rank 123` **is not a 123-place score gap.** The record says so:
`:controller-score-tie {:count 55 :rank-band [73 127]}` — fifty-five candidates
carry the chosen candidate's controller score to sixteen digits, so the rank is
a tie-break position inside a plateau. A reader given only the rank would have
overstated how far down the choice was.

`:distinct-candidate-keys 140` against `:candidate-set-size 145`: the
`[type target]` join key is **not injective** on this field —
`[:learn-action-class nil]` occurs six times. The producer therefore takes the
*best* rank for a repeated key rather than `into {}`'s last-wins, and records
`:key-occurrences` so an ambiguous reading is visible instead of assumed.

## The retrospective

`retrospective.edn`. The scored claim is the one the producer writes into each
record (`:rationale/assertion`): **this decision is re-selectable** — U40's own
regret measure ("85/85 re-selections").

Result on the store: `{:refuted 3, :undecidable 1}`. The four s5 decisions
alternate between `M-wm-aif-policy-grain-compliance` and
`M-aif-policy-conditioned-eig`, so every adjudicable record is refuted by the
tick after it; the last has no later decision.

Six planted controls establish that the verdict is a detector and not a
constant, including the two that matter:

- **c4** — a later decision that never carried the chosen action reads
  `:undecidable`, never `:refuted`. Without it "refuted" would silently mean
  "the candidate was not on offer".
- **c3 vs c4** — an empty tail (`:no-later-decision-in-the-store`) and a tail
  that did not carry the candidate
  (`:no-later-decision-carried-the-chosen-action`) are named apart.

A refusal and a typed absence are each `:undecidable` for a *stated* reason
rather than scored as though they were selections.

## Determinism

`shadow-report.edn` and `retrospective.edn` are byte-identical across two
consecutive runs (`cmp` exit 0), and the shadow's own control c3 compares the
store by SHA-256 across a re-emit.
