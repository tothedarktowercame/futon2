## The shape `READINESS.edn` carries, and how to join it

`READINESS.edn` is one EDN map, `:schema :wm/run4-readiness-v1`. A consumer that
only wants the verdict needs four keys and none of the derivation:

| key | type | what it is |
| --- | --- | --- |
| `:schema` | keyword | `:wm/run4-readiness-v1`. Refuse an unrecognised value rather than guessing. |
| `:subject` | map | **the join key**: `{:board "wm-contract" :item :RUN4}`. |
| `:verdict` | keyword | `:ready` or `:blocked`. |
| `:summary` | string | one line, already formatted: `READY` or `BLOCKED-ON [line names]`. |
| `:blocked-on` | vector of strings | one sentence per blocker, each prefixed by its line name. Empty when `:ready`. |
| `:emitted-at` | string | the date the file was emitted. |

The remaining keys are the derivation, for a reader who wants to check the
verdict rather than take it: `:line-order` (the nine line names, in order),
`:lines` (each line's `:verdict`, `:blocked-on` and the values it was derived
from), and `:not-a-requirement` (facts that are reported and *not* gated — see
below).

### The voxterm join

`voxterm/server.py` `agency_backlog()` already assembles `needs_joe` from the
board rows, and the `:RUN4` row is one of them (`:owner :joe`). The join is:
read this file, and where a `needs_joe` row's id matches `:subject :item` on the
board named by `:subject :board`, attach `:verdict`, `:summary` and
`:blocked-on` to that row. It is a server-side dict merge on an mtime-cached
read — no `bb` call per poll, which is why the verdict is committed as data
rather than computed on request.

The file is small (single-digit KB) and changes only when the derivation
changes, so caching it by mtime beside `_BACKLOG_CACHE` costs nothing.

### What `:not-a-requirement` is for

Both certified runs carry a Lean-decided `:selection-discrimination` verdict and
they differ — `:defect` for `2026-09-01-s5`, `:green` for `2026-09-04-re5`.
That bears on **which run qualifies**, which the RUN4 ruling reserves to Joe at
certificate time. It is reported here so that an acceptance is not made in
ignorance of it, and it is deliberately *not* a line: making it one would be
writing that ruling here.

## Running it

```
bb run4_readiness.bb              # check the committed artifacts against the live derivation
bb run4_readiness.bb --emit       # regenerate READINESS.edn and the verdict block above
bb run4_readiness.bb --summary    # print the verdict block only
bb run4_readiness.bb --probe      # re-take the Lean axiom probe receipt
bb run4_readiness.bb --negative   # the plants; exit 1 if any is not caught
bb run4_readiness.bb --negative --emit   # and write negative-controls.edn
```

Exit 0 all clear, 1 on any failure — the house convention. A `:blocked`
**verdict** is not a failure; it is the answer.

## The negative controls

`negative-controls.edn` holds the plant table. Each plant perturbs one input in
a copy of the world and must produce a blocker on its named line that the
unperturbed derivation does not carry — "already red for another reason" does
not count as caught, which is what makes a plant against
`:closability-audit` (red today) meaningful.

comparison disabled the suite reports `9 of 10 plants caught; MISSED N1` and
exits **1**; restored, it reports 10 of 10 and exits **0**.
