**T1 settled — what AIQA actually is.**

AIQA is an **observability + evaluation platform for *applied* AI (LLM apps)**. Concretely, from the code:

- **Tracing / observability.** Client libraries (JS/TS, Python, Go, Java — separate `aiqa-client-*` repos) instrument an AI app; spans ship via **OpenTelemetry** to **ElasticSearch** (`README.md`; `server/src/db/db_es.ts`). The local server speaks OTLP on `:4318`.
- **Eval harness.** datasets → examples → experiments (`server/src/experiments/`; `server/src/routes/experiments.ts`; MCP `create_dataset` / `create_example` / `create_experiment`).
- **Scoring includes "AI judges AI".** Metrics are typed `javascript` (sandboxed via vm2), `llm` (**LLM-as-Judge** — `server/src/scoring.ts`; `server/src/common/llmPromptTemplate.ts`: *"You are an LLM-as-Judge rating an AI assistant's output…"*; `ScoreResponse.schema.json` → `{score 0–1, message}`), or `number` (not yet implemented).
- **Statistical QA.** A Python/FastAPI report-worker computes **drift & coverage** via PCA + k-means + **Jensen–Shannon divergence** over embedding vectors (`server-python/aiqa_report_worker/analysis.py`).
- **Agent-in-the-loop.** An **MCP server** lets Cursor / Claude Code query traces, datasets, experiments, and trace stats (`mcp/README.md`).
- **Philosophy.** The "AI Testing for Adults" talk (`doc/ai-qa-talk.md`) frames testing as an *investment decision* (ROI on time and risk); test-like-{Investor, Doctor, Punk/red-team, Criminal, Grandma, Robot}; and names why AI testing is hard — unpredictable behaviour, an open-ended range of correct outputs, and qualitative performance that needs judgement.

**Answer to Joe's fork.** Of the two horns — "QC *by* AI for AI-produced software" vs "new approaches to building AI with better guarantees *by design*" — AIQA sits on the **first**, refined: it is QC *of applied-AI behaviour and output* (not of AI-produced *software*), empirical and largely **post-hoc** (observe production traces; eval against datasets; detect drift), and it *does* use AI to QA AI (LLM-as-judge). It is explicitly **not** the second horn: there is no build-time spec or verification layer — nothing that establishes guarantees *before* building. That a-priori pole is exactly where FUTON's quality-by-design (core.logic verified specifications; `logic-model-before-code`) and GLAIVE's formal verification live.
