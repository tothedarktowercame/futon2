# Runner phase coverage: discovery, 2026-09-20

Surveyed futon2 `d5c3ecd2f14e06d0ba28b3e3fcdf34723edf635e` and the current futon3c runner service. Static call-site inspection only: no JVM, click, reload, or data mutation. Line references below refer to that Futon2 revision. This document is a discovery result, not an implementation specification or a new E02 acceptance ruling.

## Finding

Phase telemetry already exists outside the tick record. Some substantive inputs and outputs also survive in cohort checkpoint events, close manifests, job evidence, and conditional repair/trip reports. Neither fact establishes complete phase input/output coverage. The tick record is a selective projection of a richer runner result, and the phase logger records transitions, not arbitrary thunk arguments/results.

There are **28 distinct `run-phase!` phase names**, plus an explicitly emitted `:opportunity` envelope. These are not the five required checkpoints, the judge's R-node route, or the service's lifecycle/status labels. Repetition and omission are normal: readiness can run twice, retries and repairs have additional occurrences, and failure can prevent later phases entirely.

The quoted E02 criterion does not, by itself, define “node” as “runner phase.” I found no executable equivalence between those concepts. The bounded cascade-evaluation claim is supported by its own records; expanding it to whole-run coverage requires the owner to declare the coverage universe. Instrumenting only the 28 wrappers would still omit substantial work performed between them.

## What a boundary actually records

[`run-phase!`](../../../src/futon2/aif/full_loop_runner.clj#L286) emits a start event, invokes a zero-argument closure, optionally projects its return through `result->event`, emits an end event, and returns the original result. An exception emits an error end event and is rethrown. Start/end records contain timestamps and context; end adds duration/outcome, or exception class/message. They do **not** automatically contain the closure's captured inputs, return value, ex-data, dependency versions, or a model.

[`emit-phase!`](../../../src/futon2/aif/full_loop_runner.clj#L268) reports status, invokes tripwire observation, writes through `:phase-log-fn` or `:phase-log`, and appends to an in-memory phase-events atom. The default log is `data/wm-full-loop-phases.edn.log` (line 53; configured at 252). Futon3c's `phase-sink` (`src/futon3c/wm/runner_service.clj:170`) updates status and delegates/appends the event. A configured delegate determines its own durability. A tripwire/logging failure at emission can prevent the thunk or its end event; do not manufacture a normal start/end pair afterward.

Early events have opportunity/trigger context; attempt/execution identity is added at runner line 3407. An event timestamp dates the event, not necessarily every external read within its closure. `run-phase!`'s `:ok` means the closure returned, not that a returned job succeeded or an effect was independently verified.

In the table, **FR** means `src/futon2/aif/full_loop_runner.clj`. Every listed timed boundary starts and ends through FR:286–306 at the indicated call site. **CP** means a cohort checkpoint term (judgment plus ground), persisted only through the enabled cohort path; it is not automatically copied wholesale into the tick record. The required CP names are `:selection`, `:construction`, `:dispatch`, `:build`, `:adjudication` (FR:64). There is also the initial time-step and close event.

## Lifecycle labels and work outside the timed inventory

- `:opportunity` is explicitly emitted at FR:3312 and normal close FR:3690. Its end can contain a tripwire snapshot. It is an envelope, not an additional `run-phase!` thunk; exceptional/early exits need not produce its normal end.
- **`starting` is service state**, set before the worker starts (`futon3c/wm/runner_service.clj:468`). There is no runner phase thunk with that name.
- **`close` is not a `run-phase!` name.** Runner close-core/close catch paths assemble briefs, findings, retention, manifests and cohort close events (FR:3454 onward; fallback at 3700 onward). Service `close-click!` (service:373) clears `:phase` to nil and uses `:close` as the registry-publication stage. These meanings must not be merged into a fictional timed phase.
- `build`, `dispatch` and `adjudication` are checkpoint names, not identically named timed wrappers. A checkpoint can summarize several phase occurrences and between-phase checks.
- Outside wrappers: dispatch-seat registration and runner-source drift refusal before core; cohort/time-step creation; measurement start/finish; source/action admission and occurrence minting; selection persistence; construction wiring/shape/correspondence checks; prompt creation; repo-head observations; job completion/refusal checks; build-cure validation; review execution/standing gates; historical-verification paths; brief queueing, close retention and tick-file publication. A whole-run claim must account for these or explicitly exclude them.
- The selection wrapper crosses into `scripts/futon2/report/war_machine.clj`: `generate-war-machine` feeds scan/judge; `judge` loads declarations and assembles/selects; `cascade-decision` runs per-target lanes and the joint scorer; `select-and-record-cascade!` reads/writes habit. Judge R-tags are **not runner phase events**. Cascade evaluations have their own bounded state/kernel/model receipts, rather than one receipt for the entire scan/judge program.

## What `:route` is, and why the single edge exists

`observed-route` (FR:320) converts adjacent pairs of node tags into edges. `packet-run-route` (329) prefers selection judgement `:wm/route`, otherwise supplies special packet/repair/historical tags, and may append a TRACE tag. `persist-run-record!` (499) uses those edges if any exist; otherwise `terminal-fallback-route` (406) supplies two tags, usually RUNNER and FULL_LOOP_CLOSE. Adjacent-pair conversion of two tags gives **exactly one edge**, with the result's outcome as `:via`. It does not mean only one phase ran.

The ordinary selection-cell projection at FR:3934 retains controller decision, selected action, ranked candidates and selection reasons, but **does not copy the judgement's `:wm/route`**. Thus the judge can have route tags while the selection CP supplied to packet-run-route does not. A missing trace-path and absence of a special packet route then lead directly to the RUNNER → FULL_LOOP_CLOSE fallback. A singleton tag also produces no edges and invokes the fallback. The writer intentionally guarantees a terminal route rather than treating no route as proof of no execution.

The judge's own route tags identify computational/model diagram nodes: scan R20/R12 (`war_machine.clj:7108,7125`), judgement tags including R8, and optional TRACE. They do not correspond one-to-one with the 28 phase labels. Route edges carry from/to/via/time, not phase inputs, outputs or model identity.

**Recommendation: retain `:route` for its existing meaning and use a separate ordered `:phase-traces` carrier if whole-run phase coverage is commissioned.** Repeated phase names need occurrence IDs and nesting/parent relationships; start-without-end and non-executed branches need honest statuses. Link existing checkpoint/event/job/receipt identities instead of duplicating or renaming their evidence as route edges. This is a shape recommendation for review, not authority to implement it or declare E02 complete.

## Where an honest retrospective report must stop

No timed wrapper generally retains its exact closure inputs and return. Some can be reconstructed only partially from CPs/jobs/findings; that is not read-time provenance. Readiness refresh, preflight, preference refresh and polling are especially dependent on mutable external state. Re-reading those sources now would describe a new observation, not the original phase input.

Preference-refresh suppresses exceptions into nil, so its current record cannot report whether a nil denotes no change or a swallowed error. Stop-line resolution/validation discard per-item returns through doseq; their only honest outputs are nil plus independently located effect evidence. Recovered dispatches and skipped waits must not claim an invocation/poll that never occurred. A phase that failed before producing a return has an error outcome, not an invented empty output. A phase never reached is not a completed phase with absent inputs.

No global model value is threaded through all 28 phases today. Scoring has its model; Git verification, transport, availability and persistence have contracts/configuration and code identity instead. Reporting the same A on all of them would invent semantics. The existing close model-unthreaded marker makes this limitation explicit.

This leaves real phase-coverage work, but not a blank slate: establish the accepted node universe, then join the existing evidence and instrument only the unrecorded boundaries. Merely expanding `:route`, or copying timestamps onto inferred inputs, cannot substantiate a whole-run E02 claim.
