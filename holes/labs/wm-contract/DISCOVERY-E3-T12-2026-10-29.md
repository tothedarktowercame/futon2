# Discovery: E3-T12 no-progress detector (2026-10-29)

## Finding

T12 is meant to stop a fifth opportunity from following four consecutive
selections of one target which produced no grounded change. The durable facts
needed for that decision already exist in run records: selected target,
terminal outcome, typed run-output grounding status, and terminal commit
absence/presence. The smallest calibrated implementation reads completed,
sealed run records at the existing opportunity-start observation, resets its
streak on a different target or a grounded commit, and witnesses after exactly
four consecutive zero-grounding records. It need not invent a numeric
`grounding-count` or infer progress from closure alone.

## 1. Charter and history

The registry title is **“four-opportunity zero-grounding target wedge”** and
T12 is explicitly `:enabled? false :status :chartered-stub`
(`src/futon2/aif/tripwire.clj:89-106`). Its complete mission charter says:

> “Same target selected in at least four consecutive opportunities with zero
> grounded changes. Chartered from shadow run 3 under the incident→neuron rule,
> but registry-disabled until a calibrated detector can distinguish productive
> multi-turn work from a true soft wedge.”

(`holes/missions/M-wm-tripwires.md:88-92`). The current code repeats the reason:
implementation waits for that calibrated distinction and returns `nil`
(`src/futon2/aif/tripwire.clj:576-579`). The restart note says to enable it only
after implementing its predicate (`holes/TN-War-Machine-Restart.md:106-112`).

`git log -S'T12' -- src/futon2/aif/tripwire.clj` finds exactly one introducing
commit, `6d1a4f3c3` (“S3b ...; T12 stub”). Its introduced code is the same disabled
registry entry and `nil` evaluator above: it was deliberately chartered, not
later disabled after a false positive. Searches for `T12`, `zero-grounding`,
`four-opportunity`, and `soft wedge` found no specification in canonical
`mathlib4/DarkTower`; the authoritative prose found in canonical futon2 is the
mission charter above plus GRID. GRID says repetition must do useful work or
explain exhaustion, and unchanged re-selection after refusal is a violation
(`holes/labs/wm-contract/GRID-wm-criteria-completeness-v2.md:51-54`).

## 2. What “no progress” can observe

Use a conjunction, not one proxy:

1. target identity: `[:decision :chosen :target]`, persisted by
   `persist-run-record!` through `chosen-summary`
   (`src/futon2/aif/full_loop_runner.clj:1404-1415`);
2. no grounded change: `:run-output` is
   `{:schema :wm/run-output-v1, :status :absent,
   :reason :run-not-grounded, ...}` and the terminal receipt has
   `:commit {:absent :no-grounded-commit}`; these are attached by
   `persist-run-record!` (`src/futon2/aif/full_loop_runner.clj:1360-1364`,
   `:1506-1515`);
3. retain `[:terminal-receipt :outcome]` as explanatory evidence. Closure is
   useful context, but it is not a substitute for the grounded-commit fact.

There is no durable numeric `:grounding-count` in these records. A search of
canonical `data/wm-runs` found the typed grounding carriers above, not a field
named `:grounding-count`. Absence/unreadability must therefore be unknown, not
zero.

## 3. Existing wire contract

T7 is the closest enabled example. At `:opportunity/:start` it consumes
`:cohort-history` and closed repair IDs, and returns a witness after three
identical open stop-line selections with no fresh commit
(`src/futon2/aif/tripwire.clj:330-351`). `cross-run-observation` supplies its
bounded history at that phase (`src/futon2/aif/tripwire.clj:1230-1289`). Each
evaluator returns zero or more witness maps; `evaluate-wire` normalizes this to
a vector (`src/futon2/aif/tripwire.clj:633-642`).

`observe!` merges the phase record, snapshot and cross-run evidence, evaluates
enabled wires, and takes the first witness (`src/futon2/aif/tripwire.clj:1433-1455`).
The durable firing records wire id, witness and observation; default action is
`:record` (`src/futon2/aif/tripwire.clj:30-38`, `:1317-1336`). With a debugger
attached it records first and stops for restart/self-heal; each disposition is
also recorded (`src/futon2/aif/tripwire.clj:1458-1529`). Otherwise the default
continues; explicit halt mode throws a typed `:tripwire-tripped`
(`src/futon2/aif/tripwire.clj:1338-1365`, `:1560-1603`).

## 4. Bounded implementation repair

Implement T12 at `:opportunity/:start` over the latest completed run-record
stream: require four adjacent readable records with one non-nil chosen target,
the exact typed no-grounding carriers above, and no grounded-commit reference.
Reset on a different target or grounded commit; refuse to classify malformed,
unsealed, or absent evidence as zero. The bound is **four completed
zero-grounding selections; the witness occurs before a fifth opportunity**.
Include run ids, target, outcomes, record pins and grounding carriers in the
witness so calibration can distinguish a real multi-turn commit from a wedge.

The supported repair route already exists: the attached debugger turns the
witness into a stop and runs the restart/self-heal interaction
(`src/futon2/aif/tripwire.clj:1458-1558`). Without a debugger, `:record` is not
enforcement, as GRID warns (`holes/labs/wm-contract/GRID-wm-criteria-completeness-v2.md:70-74`).
For an autonomous claim, configure a stopping action or use the R20 admission
boundary, whose `check!` returns a typed refusal and durable discharge
(`src/futon2/aif/tripwire.clj:1186-1210`). Do not mint an unrelated injury from
the detector: the debugger/self-heal route owns diagnosis. The current manual
exception is explicitly limited and cannot close implementation
(`holes/labs/wm-contract/E-wm-criteria-completeness.md:46-56`); its current
pre-author safeguard says HOLD if the supported stop cannot be observed
(`holes/labs/wm-contract/run001-v2-disposition.md:37-41`, `:56-59`).
