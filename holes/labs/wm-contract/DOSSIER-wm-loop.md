## Goals, in order

- **G1 — one click that works end to end.** One ordinary Trial click selects with the canonical G (Lean `GOverCascades.cascadeGrainG`, outer `OuterSelectionCanonicalG`), executes, observes, updates the belief, and leaves a record whose every term matches C1–C7 below.
- **G2 — the machine in a loop.** Two or more consecutive clicks with no hand between them, where click n+1 starts from what click n left (`R20Run.Carries`) and selects afresh; the run is `R20Run.RunCertified`.
- **G3 — self-upgrade.** The loop selects and completes work on its own code, warranted by patterns. Not itemised yet: it is reached through G2.

## Rules for this file

1. **A new finding gets a row only if it breaks one of the Lean terms below** (a code site, test or live-record field that does not do what the term's declaration says), with the evidence. A finding that only stops a click, without breaking a term, goes to *Parked* or to the row of the term it touches. (Changed 2026-10-23 from "blocks G1 or G2".)
2. Each row names: the Lean declaration, the code site, the conformance test, and the live-record field it is checked on. Done means all four agree.
3. G1 rows come before G2 rows. Discovery is a step inside a row and ends in a finding, not in code.
4. When a row's state changes, write the commit or record in the same sitting.
