# In-loop interpretation: construction consumes an agent's receipt once

## 1. Position and ownership

Today `full_loop_runner.clj:3920-3940` runs construction in the runner's process, after selection and the action-occurrence mint. Its default constructor calls `cascade-lane` once with budget 6 (`futon2/src/futon2/aif/full_loop_runner.clj:1539-1549`). The lane obtains a query and invokes the Python constructor (`futon2/scripts/futon2/report/cascade_lane.clj:469-490,67-94`); this is a synchronous subprocess, **not an interpreting agent**. The query adapter uses cached sorry state or mission title/Status and an id fallback (`cascade_lane.clj:309-345`). Python constructs then clips a cascade (`futon3a/holes/labs/M-memes-arrows/cascade_serve.py:24-43`); induced edges are not the ruled organiser (`futon3a/holes/labs/M-memes-arrows/cascade_construct.py:168-181`). The build author is dispatched only later through Agency `/api/alpha/bell` (`full_loop_runner.clj:1131-1143,4153-4185`), with configured author/reviewer defaults at lines 43-45. A T-ticket already has a target adapter (`full_loop_runner.clj:1623-1641`). Special action constructors at lines 1445,1479,1485,1528 must keep their distinct contracts.

**Proposed sequence for ordinary mission/ticket actions:** controller-authorized entry → pin target and repository inputs → retrieve from tension → one Agency interpretation job → validate receipt → ruled organise on that interpreted input → existing fold/wiring validation → construction checkpoint → existing author/build/reviewer/adjudication. Put the step inside the construction orchestration, before the single organiser invocation. Replace the default lane's opaque retrieve-and-construct call for these actions; do not run it once for suggestions and again after interpretation. Expose retrieval as a reusable operation of the existing retrievers. Keep the controller-selected action byte-identical and retain selection/enaction equality (`full_loop_runner.clj:1615-1621`). An unsupported special action gets a distinct typed result, not a mission-shaped surrogate.

The interpreter uses the existing Agency dispatch/poll lifecycle, readiness and turn accounting, with an explicit interpreter identity (which may be the author); the independent build reviewer remains separate. A successful return is an artifact plus validated digest, not prose containing “done”. Persist the request/job identity before waiting. Interpretation is a construction subphase, **not** an early `:dispatch` checkpoint: append order is enforced (`futon2/src/futon2/aif/full_loop_cohort.clj:456-489`); the current dispatch checkpoint continues to mean build dispatch.

## 2. The retained contract

Propose versioned `:wm/interpreted-pattern-set-v1` and `:wm/mission-fact-observation-v1` records, owned by the existing attempt directory/checkpoint machinery. Each construction receipt retains:

| Field | Required meaning / validation |
|---|---|
| Identity | Existing action occurrence, run UUID, semantic epoch, cohort, attempt, physical data root, start-event digest; interpreter job and author; source and interpretation schema versions. Occurrence already binds run/cohort/attempt/transition/action/hash/time (`close_retention.clj:50-90`); semantic epoch exists (`full_loop_runner.clj:49`). Never join by attempt/cohort alone: the earlier census found 23 reused keys (`TN-F13-disposition-bridge-discovery-2026-09-15.md:9`). |
| Target | Exact controller action and mission/ticket source path, bytes/hash, revision, source spans and pin time. Use IDENTIFY/MAP/DERIVE or ticket problem/evidence spans; a missing section is not permission to synthesize facts from the id. |
| Retrieval | Tension query and its cited spans, each retriever/index version and digest, parameters, ordered candidates/scores and failures, agent relevant/irrelevant judgment for every returned candidate with mission and IF/HOWEVER citations. Preserve rejected candidates, not just winners. |
| Facts/q0 | Stable named proposition, source spans, affirmative/negative/unknown value, observation time/method and scope. Outstanding text can establish an explicitly stated negative, but missing evidence is unknown. Freeze the carrier before effects; never invent a fact to enable a guard. An unresolved initial fact needed for an exact q0 is a typed model hole; do not turn a ternary observation into an unjustified point mass. |
| Interpretations | Pattern path/bytes/hash and repository membership, quoted IF/HOWEVER/THEN, Boolean guard AST over declared facts, intended effect over those same facts, authority `:documented-interpretation`, author, interpretation digest. **Two existing admission constraints must be addressed explicitly.** `full_loop_runner.clj:2920-3005` captures checkpoints and files from the attempt's evidence directory, validates allowed limb records and their companions, and rejects arbitrary unknown-schema EDN at lines 2977-2989. Therefore a new standalone receipt cannot simply be dropped there. Extend that validator with strict schemas and source/companion-byte checks; construction stores its receipt reference and digest. Retain all source snapshots and interpretation artifacts through this same manifest, not a new ledger. `evidence_manifest.clj:51-89,102-146` hashes admitted sources and validates exact entries. Admission must cover failed/interrupted interpretation as well as success, through existing close/error paths.

Also `close_retention.clj:92-123` admits only the existing categorical status carrier and explicitly rejects disposition-as-state; it cannot hold named Boolean facts unchanged. Keep its current categorical state honest (`:absent` when unavailable), and retain named facts as the separately versioned, validated observation record in the **same** evidence manifest. A later bridge consumes that observation's carrier/model identity; any replacement of the close-state port requires an explicit versioned schema change, not coercion. The current runner supplies absent state/model (`full_loop_runner.clj:3541-3548`). Temporal rules require observation before close cutoff (`close_retention.clj:116-118,142-169`); source capture must finish before freezing the close.

## 3. End-state measurement without learning the label

Freeze fact definitions and measurement predicates before work. After build and independent review, invoke the evidence readers for those same facts **before** disposition adjudication; repeat the available readers on failure paths, recording unavailable evidence as unknown. Readers take source/artifact/receipt inputs, never `:outcome`, `:grounded?`, the selected prior, or predicted effects. Freeze their output before joining it to the later close disposition. This is evidence independence, not a claim that different computer processes alone provide independence.

| Fact kind | Honest checkpoint/source measurement; limit |
|---|---|
| Spec/component declared present | Source-pinned document spans and retained before/after revisions; document presence establishes documentation, not deployed implementation. |
| Implementation/test artifact exists | Build artifacts, commit and repository binding (`full_loop_runner.clj:4358-4386`); passing tests require retained command/result and scope. A file or commit alone does not establish a complete suite or a live gate. |
| Wiring assembled / holes | Construction wiring, fold output, correspondence/shape validation and sorries (`full_loop_runner.clj:3973-3991`). This measures assembled representation, not runtime loading or successful execution. |
| Gate passed | Retained gate receipt at the appropriate revision/time. Build validation exposes review gate (`full_loop_runner.clj:4370-4384`); do not rename reviewer approval into a runtime act-gate pass. Missing act-gate receipt is unknown. |
| Independent replay confirmed | Separate reviewer identity, replay command, exact tested revision and qualifying receipt. Review job/gate is available in build validation; approval alone is insufficient for a mission-specific replay predicate. |
| Pending/request recorded | Retained authoritative request/status bytes; a request is not a successful replay. |
| Mission goal discharged / capability live | Explicit independent target-specific measurement (e.g. readback or runtime probe) at the model revision. Current adjudication before/after describes the implementation entity (`full_loop_runner.clj:2669-2670,4520-4534`), so it cannot fill arbitrary mission facts. Without the specific receipt: unknown. |

For the nine-fact zaif example, these rules preserve the distinction between regression fixes, replay requested, replay confirmed, complete suite and certificate promotion; none follows automatically from `grounded-change`. The manual carrier and citations are retained in `holes/labs/wm-contract/runs/F13-model-manifest-2026-09-15/redo/interpreted-pattern-set.edn:1`. Report both complete and censored pairs; never delete failed attempts from the estimator's denominator silently. No fitting or scoring is included here. Terminal C is the supplied twelve-disposition `machineC` (`mathlib4/DarkTower/WarMachine/MachinePreferenceDistribution.lean:29-41`); this packet supplies observations for a future bridge, not new preferences.

## 4. Receipted find and ruled organise

Lean Receipt requires clause kind, acknowledged clause, route, as-of and a citation (`mathlib4/DarkTower/WarMachine/Holes.lean:269-275`). Map Clause to the exact cited IF/HOWEVER text plus source span, AsOf to the frozen target/repository revision and observation instant, TextCitation to path/byte digest/span with retained bytes. Store both antecedent clauses in the interpretation, explicitly designate which one the find receipt acknowledges. Route identifies the actual retrieval/interpretation route. Validate citations against pinned bytes and expectations derived from those sources, not against another unchecked agent assertion. `contentF2` compares the actual receipt fields with expectations (lines 332-339), and `citationF3` validates the returned citation itself (lines 354-358). This warrants source correspondence; semantic relevance still needs independent review and negative controls. Exclusion/discrimination needs an externally designated rejected pattern, not an empty set (lines 362-370).

Reuse the reference find's repository containment and receipt-extension boundary (`futon3/checks/find_organise.clj:227-258`): its `:fires?` evaluator can consume validated interpreted guards/context; its protected `:if/:route/:warrant` cannot be overwritten by agent output. Extra clause/as-of/text fields need explicit validation; merely calling the reference function does not establish the stronger Lean laws. Retrieval candidates are a proposal set, not automatically the final firing set. Future-state relevance must remain distinguishable from present guard truth, so deferred candidates do not receive fabricated present-firing receipts.

O2's input is **four** values: previous cascade, selected candidate action space, pinned authored repository, explicit externally admitted set (`F12RuledCarrier.lean:21-37`). Feed validated find membership plus interpretation references into the selected carrier, retain the actual prior cascade (or explicitly identified first-attempt empty carrier), and record admissions with their authority; no implicit emptying of an existing admission set. Output retains selected/added/admitted separately, authored stands-on and organised edges, precedence before/after, and ordering/score evidence. Test no-bootstrap fastForward over nodes minus added nodes. The old runtime three-argument organiser (`futon2/src/futon2/aif/cascade_policy.clj:60-93`) is not this adapter. Interpretations alone do not supply precedence or externally admitted authority; missing inputs are holes. This design closes the input route to O2, not its conformance proof by assertion.

## 5. Typed outcomes, recovery and time

Proposed construction findings: `:interpretation/agent-unavailable`, `:interpretation/no-relevant-pattern`, `:interpretation/genesis-required`, `:interpretation/budget-exceeded`, `:interpretation/source-changed`, `:interpretation/invalid-receipt`, and `:interpretation/unmeasurable-fact`. Each carries attempt/occurrence/job, stage, source refs, elapsed time, partial artifacts and next action. Keep the existing close disposition vocabulary: findings live beneath a compatible existing failure outcome; do not add these keywords to C. Genesis is bounded work inside the interpretation job when authorized by the attempt; if it cannot complete, retain the named gap and stop construction. No fallback to the previous constructor under a receipted label.

Current Python timeout defaults to **30 seconds** (`cascade_lane.clj:33-37`); `run-phase!` measures elapsed time but imposes no overall phase deadline (`full_loop_runner.clj:272-291`). Agency polling has a **45-minute absolute per-job recovery budget** by default (line 48; lines 1204-1238), and a read request has a 10-second timeout (line 1194). Expiry suspends as incomplete and does not cancel the job. Thus the agent cannot be nested inside the Python timeout. Its added latency is retrieval + one Agency queue/execution interval + validation; **no measured duration or acceptable production bound is available from this read-only design**. Reusing the 45-minute per-job budget is technically compatible with the runner but can add that much waiting, plus request/poll overhead; it is not evidence of acceptable click latency. Preserve elapsed/queue/validation measurements and the declared budget on the first commissioning click. Do not silently increase existing budgets. Retain and resume the same job after expiry; count interpreter turns in the same accounting used for author dispatch (`full_loop_runner.clj:4167-4171,3534-3535`).
