## What did not work, and what did

A Voronoi partition over a 3D down-projection of the mission landscape did not factor the
work (Joe). Today's partition did, and it used no geometry: a row is placed by declared
relations that a probe can check or a reading can cite — its Place (alive or gone), its
situation, its decision and carry, its wing. The unit that produced every row was one item
read against one question with the answer cited to a file and line. That unit is the ant.

## The ant

One stem in, one row out. An ant is a seat (Zai or Kimi) given exactly one item and one
question kind, and required to return a fixed-schema row in which every field that asserts
something cites `path:line` or a commit. "Unsure" is a legal value for any field and beats
a guess. No ant reads more than its item and the files that item names. Fable does not read
the pile: Fable samples one row in ten for adequacy (coding-handoff job 2) and reads any row
whose citation check fails.

Output schema (one EDN file per ant, `futon3c/holes/excursions/ant-reads/<stem>.<kind>.edn`):

    {:stem "E-..." :kind :place :seat "zai-3" :at "2026-11-03T..Z"
     :fields {...per kind, each value {:value v :cite "path:line" | :unsure "why"}}
     :files-read [...] :confidence :high|:medium|:low}

The partition export (`futon3c/scripts/giraffe-partition-export.py`) merges ant rows into
the page the same way it merges decisions and probes, so each ant's work is visible as a row
with its date and seat, and the readability standard can sample it.

## Why this is AIF ants, not a reading job

Each ant is one observe→perceive→affect→policy step on the field: it observes one stem,
perceives it into typed fields, reports affect as confidence and `:unsure`, and the policy is
the kind chosen for it by the row's `needs` column. The pheromone is the row's state moving on
the page (unplaced → placed; close → witnessed; place-gone → rehomed). No ant needs the whole
field, and the field needs no Fable to read it; it needs the probes (facts), the ants
(readings with citations), and the sample (judgement).

## Harness: reuse zaif-build-loop, do not fork it

`futon2/holes/labs/zaif-harness/zaif-build-loop.sh` already does the shape: one board row
per invocation, a WORK seat and a REVIEW seat that must differ (R9 self-certification
refused), gates before acceptance, stop bells to the lane owner. Per the fork discipline, the
plan parameterises it rather than copying it:

1. **Board**: `ant-board.edn`, generated by a script from the partition JSON and the draw
   pile: one row per (stem, kind), with `:prompt-file` per kind.
2. **Prompts**: `ant-prompts/A1-place.md` … `A6-acceptance-check.md`, each ≤ 40 lines: the
   item, the files it may read, the schema, the citation rule, "unsure beats a guess".
3. **Work seat**: zai (after the cap resets 2026-11-03 02:04Z) or kimi via
   `futon3c/scripts/kimi-task.sh` (unique requisition). **Review seat**: the other family,
   checking mechanically that every citation resolves (`path:line` exists and contains the
   quoted text) and the schema validates; it does not judge adequacy.
4. **Sample**: Fable (claude-2) reads one accepted row in ten and every citation failure.
5. **Merge**: the export reads `ant-reads/` and the page shows the row with seat and date.
6. **Stop**: the loop stops on a schema failure rate above 20% in any ten rows, or on any
   row that names futon1a as a dependency.
