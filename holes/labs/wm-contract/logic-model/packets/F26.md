Design:
- L (`src/futon2/aif/meta_injury_ledger.clj`): `allowed-predecessors` gains
  `:reopened #{:enacted :claimed}`. A `:reopened` entry whose predecessor is
  `:claimed` must carry `:reason :author-failed` and `:port-receipt-pin` (a
  pin); `validate-ledger` (line 262) reports `:reopen/author-failure-evidence`
  when either is missing, and `:reopen/reason-unexpected` when a reopen from
  `:enacted` carries `:reason :author-failed`. The attempt-increment rule
  (line 105-107) and `append-retry-result` (line 345: reopened, or `:abandoned
  :attempt-limit-exhausted` at the limit) are unchanged and are the path used.
- C (`meta_repair_coordinator.clj` line 320): when the author receipt is not
  `:succeeded`, before `held!`, append through `ledger/append-retry-result` the
  proposed entry `{:injury-id .. :repair-id .. :reason :author-failed
  :port-receipt-pin (:receipt-pin author-receipt) :injury-predecessor
  {:entry-id .. :entry-pin ..}}` built the way the enact path builds its
  proposed entry (C:415-425), then `held! :author-failed :author <appended
  ledger> tx1 author-receipt`. `settle` in P (line 1087) already persists the
  ledger and transaction a held result carries. A refused append stops with the
  existing `:coordinator/ledger-transition-refused`.
- P (`meta_self_heal_production.clj` line 1053): a resumed transaction whose
  `[:work-order :attempt]` is below the ledger's latest `:attempt` for its
  `:injury-id` (the ledger reopened past it) is retired, not resumed: rename
  the file to `<transaction-path>.attempt-<n>.retired.edn` and prepare as if
  no transaction existed. `coordinator/prepare` (C:131-145) reads `:attempt`
  and `:repair-id` from the ledger's active entry, and the futon3c adapter
  mints fresh sessions per click (`claim-session`, A:718), so attempt 2 needs
  nothing else. Put the retirement on the disposition as `:transaction-retired
  {:path .. :attempt n}`.
