## Handoff contract (applies to every packet)

Each numbered packet below is **one turn**, one reviewable behaviour, within one
phase or across the single named producer/consumer interface. Dependencies are
listed explicitly; numbering is a topological order, not a request to serialise
independent work. Scope cannot expand because a later consumer refuses.

- **C — Codex code packet:** worktree under `~/worktrees/futon2/<packet>` (or
  the owning repo); run clj-kondo on changed Clojure and check-parens via
  `/home/joe/code/futon4/dev/check-parens.el` on changed Lisp/Clojure; run the
  named focused test namespace once per candidate, not a suite. Python-only
  packets use one focused test module; non-applicable gates are marked N/A.
  **No warrant registration unless Joe asks.** A failed test is reported/fixed,
  not repeatedly rerun unchanged. No new marker-keyed bypass.
- **R — Sonnet or Zai reading packet:** one bounded source/document comparison;
  deliver cited conclusions and an explicit counterexample. No runtime mutation,
  new theory-by-default, or suite run. Clojure gates N/A unless scope is separately
  changed to code. Documentation links and diff checks are the gate.
- **Verification:** a fresh test JVM checks the constructed bad case only. The
  route check is in the serving JVM, debugger attached, from landed main, without
  spending a click. Use a read-only or isolated-output invocation of the named
  boundary with real serving inputs; stub outbound dispatch in a diagnostic.
  Never mint production fixture evidence. Reload only when no click is running.
  Live-click expectations below are for the **next separately authorised click**,
  not instructions to fire one per packet. If unreachable, report not reached.
- **Bell-back:** commit SHA, changed symbols, test command/result, serving probe
  result (or exact reason deferred), changed table row IDs, remaining frontier.
  codex-1 updates the named model rows in the same sitting. Code and model land
  together, or the model commit names the code SHA and the handoff names both.
  No claim is upgraded from static to live without a run ID and retained evidence.
- **Common next-click envelope:** eligible/assessed/reading-absent counts with
  IDs; additional exclusions counted separately; selected target/policy; last
  reached phase; original stop kind, if any. Counts come from that click's own
  record, never an earlier probe. All packets preserve this envelope.
