# C164 — challenge to the five glossary blockers

Date: 2026-08-31

This re-reads C155's five `blocked` entries using four disjoint causes: missing
carrier, undecided semantics, refused implementation, and not a formal term.
`Blocked` is not retained as an explanation by itself.

| entry | revised class | precise reason |
|---|---|---|
| Embedding space | **not a formal term** | The glossary calls an embedding an optional exploratory proposal mechanism, neither foundational nor required. The repository has several incompatible concrete embeddings (visual-layout coordinates, MiniLM/BGE relevance, structural SVD, and proposed graph embeddings). There is no single glossary object awaiting definition; formal obligations belong to whichever retrieval/proposal implementation is selected. Counting `Embedding` as missing vocabulary was an overstatement. |
| GFlowNet “slush” | **decision not made** | The implementation family exists, including a trusted trainer and both null and positive experiments. What is unset is the canonical trajectory state, terminal object, conditioning, and reward whose normalized flow would count as the War Machine proposal distribution. `ProbabilityKernel` could carry the result, so this is not a carrier absence and not an implementation refusal. Defining it now would promote one experimental reward/conditioning choice. |
| Substrate and Drawbridge | **decision plus missing boundary carriers** | Concrete L1 files, L2 hypergraph entities, authenticated queries, and `Layer.L1/L2` exist, but no formal carrier identifies which L1 objects project to which L2 records or which capability authorizes each read/write. The decision is the authority/projection boundary; after it, the missing `SubstrateObject`, projection, capability, and guarded-operation carriers are mechanical. This is not a refusal and is formalizable, but not before that boundary is chosen. |
| Demonstration Foundry and have–want arrows | **definable now (missing Lean carrier)** | The supposed blocker is already decided by serialized practice: a have/want pair has two referenced endpoints plus an operation/provenance, and composition matches one arrow's wanted endpoint to another's available endpoint. `cascade_lane.clj` and the meme-arrow records supply the carrier shape. Lean needs `HaveWantArrow`, an endpoint-match/composition relation, and an outcome tag; it does not need the external scanner implementation. C155 incorrectly treated cross-repository location as semantic underdetermination. |
| Strategic mission selection | **missing carrier family** | The live additive selector is implemented and dry-runnable, but the glossary explicitly refuses to identify its centrality/fit/doability surrogate with canonical strategic AIF. The missing family is `StrategicOutcome`, `StrategicPolicy`, strategic `Q`, `G_S`, `E_S`, and the conditional tactical-policy carrier. The existing generic kernels can be reused, but the strategic outcome type and policy grain do not yet exist. This is not a refusal of selection itself; it is a carrier gap, analogous to C42. |

There are **no refused implementations among the five**. `find` and `organise`
remain deliberate implementation refusals, but none of these entries requires
overturning them merely to define its vocabulary.

The C155 partition therefore changes from **6 definable / 5 blocked / 3 not
formal** to **7 definable / 3 blocked / 4 not formal**:

- Demonstration Foundry arrows move to definable-now;
- embedding space moves to not-formal;
- GFlowNet slush, Substrate/Drawbridge, and strategic selection remain blocked,
  now respectively by one named modelling decision, an authority-boundary
  decision followed by carriers, and a missing strategic carrier family.

No declarations, bindings, or paper text change in this pass.
