## 1. The question

RUN9 retired the `:free-energy` row (scalar F, node R8) on Joe's J2 ruling, and the
replacement F_π is realised and run. The code still computes F every tick. I5 asks,
before anything is removed: **who reads `:variational-free-energy` off a record, what
does computing it cost per tick, and does anything outside futon2 join on it.**

## 5. Cost, measured

Per-tick compute, on the real input shape (8 channels, the latest record in
`data/wm-trace/wm-trace-2026-09-01.edn`), 10^6 calls after a 10^5-call warmup:
**264.28 ns per call**, one call per tick. Against a mean instrumented tick span of
**14.22 s** over the twenty S1b records (`runs/2026-09-01-s1b/wm-trace-s1b.edn`,
first to last route stamp; min 13.12 s, max 15.56 s), that is **1.9 × 10⁻⁸ of a
tick**.

Storage: pr-str of the latest record with and without the key — **1,046,162 bytes
vs 1,046,117, a delta of 45 bytes, 0.0043%**.

Recomputation from the stored inputs is exact: recomputed
`0.2779264186395668` = stored `0.2779264186395668` on that record.

**So cost is not an argument for removal.** If the computation goes it should go
because it is a shortcut Joe ruled out (J2), not because it is expensive; nothing
here is.

## 6. The consequence nobody had written down: removal changes the recorded route

`war_machine.clj:4915` stamps the `:R8` route hop with
`"futon2.aif.free-energy/compute-variational-free-energy"`, and that is the **only**
`:R8` route tag in the file. The S1b route (all 20 ticks, same path) runs
… `:R7` → `:R3` → `:R8` → `:R5` … so its consecutive-pair hops include `R3→R8` and
`R8→R5`.

Checked against the topology RUN3 reads at run time
(`p4ng/empirics-futon/control-map-edges.edn`, 22 drawn edges):

- `R3→R8` — **route-measured** (`:route-measured-drawn`)
- `R8→R5` — **drawn** (`control-map-edges.edn:41`)
- `R3→R5` — **neither drawn nor route-measured**

So if the computation is removed and its route tag with it, the next run's route
contracts to … `R7` → `R3` → `R5` …, and RUN3 classifies `R3→R5` as `:unmapped`
(`run3_conformance.bb:116-124`, topology loaded at `:52-62`) — **NOT CONFORMANT,
exit 1**. Run through that exact classifier rather than reasoned: `[R3 R8]` →
`:route-measured`, `[R8 R5]` → `:drawn`, `[R7 R3]` → `:drawn`, `[R3 R5]` →
`:unmapped`. That is a
figure-and-registry consequence, not a code detail, and it is the reason the next
slice cannot be "delete the defn": the removal has to say what R8 is tagged at
afterwards (the F_π computation is the candidate — `war_machine.clj:5095-5096` —
but it sits *after* `rank-actions` at `:4999`, so the hop order changes too), or
the drawn edge changes.
