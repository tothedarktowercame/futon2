Joe's observation chain: README-inbox-zero was modeled as a "zero

## Four lenses, one object

Zero theorem, AIF model, board, peripheral, institution — these are
not five things but five views of one shape: a bounded loop you enter,
act in under typed rules, and leave with receipts.

- AIF view: a Markov blanket with beliefs, a regulated variable, and
  precision-weighted channels (inbox-zero: coherence of host-vs-record).
- Board view: chips + wires + fuel, a named terminal (zero/clean).
- Peripheral view: a constrained capability envelope with entry/exit
  keyword sets and a hop protocol (PeripheralSpec — the actual shape
  on disk).
- Institution view: positions, rules, participation records.
The lenses compose because the object recurses (the expansion-board
ruling): a module is a board; a board's chips can be modules.

## What "kernel" means concretely (the design claim)

The WM as kernel is not "bigger module" — it is the layer that owns
what modules must not:

1. the common substrate — the one queryable self-account (▣): the
   bitemporal store every module reads and appends to, and no module
   owns;
2. preference receipt — ranked-actions, operator pins: priority is
   received at the kernel, never computed in a module (boundary 1 all
   the way down);
3. ratification and adjudication — adoption receipts, conflict
   resolution (compositor C2's "authorized resolution"), sanctions
   rulings: the aggregation authority;
4. the level registry — who is L-what, so the collapse law is
   checkable (handoff algebra R5);
5. the clocks — mission and institution lineage (the kernel mints
   attribution; modules reference it).

Everything else — inbox-zero, the verifier, the cartographer, the task
manager, future stakeholder boards, even Lean witness lanes — is a
module: a loop over the substrate, entered and exited through the
handoff algebra's four-field channels, composed under C1/C2, carrying
versioned cards.

## Why this is the natural endpoint of the current work

The kernel/module boundary IS the collapse law's boundary stated as
architecture: modules compose via interfaces (disposition + identity
reference up, I11); the kernel ratifies and never pilots (constructor
not player, at system scale). The handoff algebra becomes the module
bus; the compositor becomes module loading (institution definitions in,
carried bundles out); the sigils become the module ABI's type names.
And the proof-of-concept already ran: inbox-zero as zero theorem was
the first module through the whole stack — AIF theorized, boarded,
run live, witnessed, its failure history becoming the kernel's test
suite (C446, U59).

Not a plan; a recognition. The build order stays the one in force
(WORK-REMAINING phases, adapter adoption packet-by-packet); this note
is the shape those packets are converging toward.
