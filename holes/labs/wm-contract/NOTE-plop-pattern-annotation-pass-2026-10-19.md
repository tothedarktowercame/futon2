## What was done

Every entry of the PLoP 2026 catalogue was read in two versions, the accepted
conference text (p4ng tag `plop-2026-conference`, 36d156218) and the current
text (p4ng `sec-catalog.tex`), and annotated span by span against the code at
futon2/futon3c HEAD. Each annotation records the quoted span, a status for each
version of the text (VALIDATED, EXISTS-UNVALIDATED, ABSENT-OR-LOST, REFUTED,
UNCLASSIFIED), code anchors (repo, path, symbol, sha), a note, and any ticket.

- Data: `p4ng/plop-2026-code-annotations.json` (source of truth; also holds
  Joe's follow-ups, the revision policy and a certificate-coverage table).
- Reader: Arxana Docs book `plop2026` (`M-x arxana-docbook-open-book RET
  plop2026`), generated by `p4ng/build-plop-docbook.py`; one page per entry with
  both versions and the annotations, links opening the code.

**Caveats.** All annotations are by one reader and none has been reviewed by a
second agent. Most are from reading code, not running it; where something was
not checked, the annotation says so. Absences were established by search.

**Revision policy (Joe, 2026-10-18).** The code must be an accurate model of
active inference. A code-vs-AIF discrepancy changes the code; a docs-vs-code
discrepancy where the code is AIF-valid changes only the docs.

## What the pass found, in five themes

1. **The problems and reasons held; the prescriptions drifted.** In most
   entries the If/However/Because still describe the code, while the Then
   names a design that was replaced by a different, usually AIF-valid one: R1
   (six-key map vs per-entity categorical posterior with A and B), R2 (session
   features vs a 14-channel stack observation), R4 (shared kernel vs a forward
   model distinct from the world), R6 (pattern IDs vs policies), R13 (discount
   vs per-step normalisation), R14 (diagnostic coupling vs outcome-learned
   gain). These are docs edits.
2. **Built, AIF-valid, but off the live route.** R7 (per-channel precision
   registry), R11 (hierarchical budget arbiter), R14 (selection gain and
   Friston gamma; the live outer choice is a deterministic minimum), R17p
   (model-uncertainty bonus, default 0.0), capability zones and
   native-currency discrimination (efe route only). The live route uses
   simpler stand-ins.
3. **Certificates do not cover the off-route mechanisms, and contradict the
   tie guidance.** No Requirements Q mentions precision, budget or selection
   temperature. `OuterTaskObjective` says the outer objective is not
   cascade-policy G and makes stable task identity the tie law;
   `selectionDiscriminates` sits outside `conforms`. On the 10-18 clicks Q2,
   Q4 and Q8 were not recomputable (carriers refused:
   normalization-not-bound-to-g-terms; selected-not-strict-key-minimum).
4. **Selection ties have a mechanism.** In `outer_target_score`, unobserved
   targets share the prior alpha (255 of 327 predictions in click 5 were the
   uniform prior), epistemic value is fixed at 0.0, and the ranked `:g` folds
   engineering terms and is clamped to [0, 1]. The same failure was met and
   fixed on the efe route in July (native-currency discrimination).
5. **Apparatus failures reach the strategic belief as task outcomes** (R15).
   `meta_outcome_dataset` classes `:incomplete` and `:build-failed` as task
   outcomes, and codex-68 confirmed the 10-18 records are in the learning
   manifest and folded (mostly as `:typed-blocker`). Relatedly (R20), none of
   the ten failed readiness clicks tripped a wire, none deposited a wire or a
   blind-spot entry, and the blind-spot map was last changed on 2026-07-16.
