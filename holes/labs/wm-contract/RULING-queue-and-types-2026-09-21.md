# RULINGS (Joe, 2026-09-21 ~05:00, pre-click)

1. TARGET TYPES: the machine runs on M- / E- / T- types; the
   proposal pipeline QUEUES T- types for self-repair — repair-store
   findings surface as T-type targets whose discharge contracts are
   the ready-made acceptance bars.
2. DISCHARGE IN THE LOOP: without the runner performing the
   store-closing stage (implementation registration, review-evidence
   from the in-loop review job, resolve!), "the machine is not
   actually functional for the purpose it is intended." Build
   authorized.
3. WONTFIX: "legitimately unfixable issues should not be retained on
   any queue and can be marked WONTFIX." Dismissals carry this
   ruling as authority; each dismissal still states its per-finding
   verification (why it is genuinely unfixable/stale), never batch
   rubber-stamped.
4. The validation click WAITS on these — a machine that cannot
   consume its own queue is running hot, not working.

## ADDENDUM (Joe, ~05:50): Lean states what is to be built

On the dirichlet absence-hole: "the Lean code [is] supposed to
include a specification of what is to be built, not a certification
of whatever degenerate state happens to exist at any given point in
time." Refines the standing lean-specifies-code-conforms rule:
statements are forward requirements; degenerate present states are
dated facts in registries and docstrings, never propositions; an
absence left as sorry is bad, an absence PROVEN would be worse.
