## 6. Predictive-outcome-kernel constructor

**What it is.** The machine's model and current belief predict a normalized outcome distribution for each declared policy. Verbatim entry name: “Q(o|pi) -- the machine's predictive outcome kernel, constructed”; required signature: `GenerativeModel Obs State Action PolicyIndex -> BeliefState -> PredictiveOutcomeKernel PolicyIndex Obs` (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:65`).

**Current state.** Registry bindings are the forward-model, risk, ambiguity and expected-free-energy equations in `aif-equations.edn` (equation index below). Lean has `machinePredictiveOutcomeKernel` and normalization proofs, taking a `QReading` (`mathlib4/DarkTower/WarMachine/MachineQ.lean:187`; `mathlib4/DarkTower/WarMachine/MachineQ.lean:84`); this is real reusable composition, not a concrete production model. `MachineQWitness.lean` uses demo carriers, as distinguished by the module's names; it cannot supply the machine binding. Runtime `forward-model/predict` supplies action-conditioned channel moments, not this kernel (`futon2/src/futon2/aif/forward_model.clj:280`); scoring consumes that proxy (`futon2/src/futon2/aif/efe.clj:474`). No machine-bound normalized Q on the ruled tagged outcome domain was resolved in these sources.

**Acceptance (a), running construction.** Implement proposed `machine-predictive/predictive-outcome-kernel(model, belief, policies)` returning every policy's declared support and masses plus input/model/support pins. Compose actual post-update belief, controlled B and machine A; persist this result before `futon2/scripts/futon2/report/war_machine.clj:6384`, and have `futon2/src/futon2/aif/efe.clj:474` consume it rather than calling the old action-delta proxy for the canonical score. Row 14 owns the final consumer integration; source-only constructor completion is not acceptance of (a).

**Acceptance (b), Lean statement.** Instantiate or generalize the existing composition over the **actual** machine belief carrier; prove `Q(o|pi)=sum_s A(o|s) Q(s|pi)`, nonnegativity, exact support and row normalization. State the policy horizon explicitly; current `QReading.plan : PolicyIndex -> Action` sees one controlled step (`mathlib4/DarkTower/WarMachine/MachineQ.lean:84`), so it cannot silently stand for an entire cascade.

**Acceptance (c), production-match witness.** On a retained real tick snapshot, record all masses for two complete policies, one repeated-plan control, and a changed-state/action contrast; compare the production function with Lean reference values under identical pins. Require exact rational agreement where representable and report actual numeric deltas otherwise; missing A support or foreign model revision must produce a named divergence/refusal. A constant checkpoint distribution must fail the state/action sensitivity control when the model predicts a change. Follow the common evidence rules below.

**Locus/dependencies/risks.** New `machine_predictive.clj` reuses packet 9 output; packet 6 also owns the missing A-to-ruled-Outcome binding. Needs 7,8,9; does not mathematically need C or parameter EIG. Row 14 depends on it. The disposition checkpoint adapter explicitly declares itself constant (`futon2/src/futon2/aif/disposition_risk.clj:59`); using it to pass the positive test would reintroduce the missing state/action dependence. U92's observation encoder must agree with this A's declared alphabet, not with a retrospectively convenient label.

## 7. Belief-to-state distribution

**What it is.** Turn the actual stored belief into normalized mass on the states consumed by the model. Verbatim: “BeliefState -> a distribution the model can be run on”; signature: `BeliefState -> ProbabilityKernel Unit State (equivalently: any map from the belief carrier into the generative model's State)` (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:112`).

**Current state.** The belief-state/belief-update and forward-model registry rows describe different sides of this join. Runtime stores entity→categorical status distributions (`futon2/src/futon2/aif/belief.clj:310`); Lean `MachineBeliefState.machineBeliefState` mirrors that storage/carry (`mathlib4/DarkTower/WarMachine/MachineBeliefState.lean:25`), while `Holes.BeliefState` is Channel→mean/variance (`mathlib4/DarkTower/WarMachine/Holes.lean:7070`). `QReading.beliefMass` requests a map but does not construct the machine's map (`mathlib4/DarkTower/WarMachine/MachineQ.lean:84`). The older census's four channel predictors are partial moment readers, not a joint state distribution (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:112`).

**Acceptance (a), running construction.** Proposed `machine-belief/belief-state-distribution(model-context, stored-belief)` consumes the post-filter, post-carry belief at `futon2/scripts/futon2/report/war_machine.clj:6228`; its output is passed to packet 9 before ranking. For the narrow single-entity reading, explicitly identify the modeled target entity and use its entire seven-status posterior. Empty/missing entity and invalid mass are typed failures, not a uniform fallback. A multi-entity action requires an explicit joint-state construction or a reviewed factored model; summing/averaging unrelated entity rows does not meet this requirement.

**Acceptance (b), Lean statement.** Define the actual entity/context/state maps and prove normalization, coordinate preservation, and conservation of the selected posterior. Use the production categorical carrier rather than translating it into fictitious channel moments to satisfy the old signature. State any factorization assumptions if the machine model is joint. The entry's “equivalently” is imprecise: a map to a state value alone is not generally a probability distribution; the narrower required result is the normalized kernel.

**Acceptance (c), production-match witness.** Read actual retained posterior rows for a carried entity and a newly bootstrapped entity; compare all seven coordinates and row sums through the production reader. Include missing/deleted entity, reordered support and invalid-mass controls. Verify the exact output reaches packet 9 under the same entity/model identity; equality of an isolated adapter is insufficient.

**Locus/dependencies/risks.** New `machine_belief.clj` builds on `belief.clj` and existing carry logic; do not rewrite the stored belief just to fit `Holes.BeliefState`. Parallel with 8/10 after State/context is agreed. Supplies 9 and U92's state-coordinate binding; does not depend on accumulated counts. **Unresolved model scope:** one entity, a factorized population, or a full joint are not interchangeable. Propose explicit entity context for the initial constructor API, with a separately typed joint implementation for policies touching multiple entities; no global averaging is licensed (`mathlib4/DarkTower/WarMachine/MachineBeliefState.lean:25`; `mathlib4/DarkTower/WarMachine/MachineQ.lean:84`).

## 8. Controlled transition kernel

**What it is.** For each current state and actual action, give normalized probabilities of successor states. Verbatim: “B(s'|s,u) -- the ACTION-CONDITIONED transition kernel”; signature: `GenerativeModel-carrier level: ProbabilityKernel (State x Action) State, instantiated at the machine's own State and Action` (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:143`).

**Current state.** Lean's `TransitionKernel` is the correct generic carrier (`mathlib4/DarkTower/WarMachine/Holes.lean:7035`); recorded concrete witness modules use fixture types, not machine inputs (entry above). The live belief filter uses `transition-model-v1`, an uncontrolled seven-by-seven identity matrix (`futon2/src/futon2/aif/belief.clj:214`; `futon2/src/futon2/aif/belief.clj:310`). `predict-effects` supplies action deltas, not state transition probabilities (`futon2/src/futon2/aif/forward_model.clj:280`). The forward-model/depth/action registry rows do not themselves supply B.

**Acceptance (a), running construction.** Proposed `machine-transition/controlled-transition-kernel(model, action-vocabulary, parameter-state)` returns complete `(s,u)` rows from declared machine dynamics/learned parameters. Packet 9 applies it for each policy action; the actual belief prediction step must receive the recorded previous enacted action, not silently use identity B while policy evaluation uses another model. Initial/no-previous-action semantics must be explicit in the model contract.

**Acceptance (b), Lean statement.** Instantiate the carrier at machine State/Action and prove normalization/nonnegative mass and the exact production construction rule. Prove action distinction where the declared model predicts one; mere extra action arguments with identical ignored rows do not establish controlled dynamics. Retain the uncontrolled-kernel and beta-normalizer negative controls as rejection cases.

**Acceptance (c), production-match witness.** Replay real model/parameter snapshots over two actual action classes and all states; compare complete transition rows and one applied belief step. Include a pair whose declared effects differ, an unsupported action, and a support-order mutation. Observed failures remain typed divergences until repaired, not successful matches.

**Locus/dependencies/risks.** New `machine_transition.clj`; reviewed change to `belief/update-step` and the predictor's shared B supply. Independent of packet 7's implementation but requires its State contract; supplies 9 and 6. U91/U92 may later update learned B parameters if that is their declared target, but today's U91 is not evidence that B is already learned (`futon2/holes/labs/wm-contract/aif-equations.edn:210`). **Blocking modelling question:** no measured action-conditioned state law was found in the inspected production seams. Do not invent numeric action deltas/transition rows and call them empirical; the packet must state their model authority and distinguish declared priors from observed estimates (`futon2/src/futon2/aif/belief.clj:214`; `futon2/src/futon2/aif/forward_model.clj:280`).

## 9. Policy-conditioned state predictive

**What it is.** Push the current state distribution through the actions of a policy to predict its future states. Verbatim: “Q(s|pi) -- the policy-conditioned predicted-state distribution”; signature: `GenerativeModel + BeliefState + PolicyIndex -> ProbabilityKernel PolicyIndex State` (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:178`).

**Current state.** `machinePredictedStateKernel` now provides the generic one-step Lean sum (`mathlib4/DarkTower/WarMachine/MachineQ.lean:139`); the older census's fixture-only statement is superseded at that level. Its `QReading` still requires belief mass, shared supports and policy→one-action projection (`mathlib4/DarkTower/WarMachine/MachineQ.lean:84`). Runtime ambiguity consumes Gaussian channel variances rather than state-weighted observation entropy (`futon2/src/futon2/aif/efe.clj:474`); the depth/ambiguity registry rows name the intended consumer, not this producer.

**Acceptance (a), running construction.** Proposed `machine-predictive/predicted-state-kernel` takes packet 7's real belief distribution and packet 8's B plus the entire versioned policy plan. Iterate `q_(t+1)(s')=sum_s B(s'|s,u_t) q_t(s)` over its declared horizon; retain each step and terminal distribution. Supply 6 and the canonical ambiguity consumer at `futon2/src/futon2/aif/efe.clj:474`, reached from `futon2/scripts/futon2/report/war_machine.clj:6384`.

**Acceptance (b), Lean statement.** Reuse the existing one-step proof and extend by induction over the actual policy action sequence. Prove zero-depth identity, one-step agreement, normalization at every step, and equality for equal full plans. Do not prove a one-step theorem and label it full-policy prediction.

**Acceptance (c), production-match witness.** Compare every state mass at depth 0,1 and an actual multi-step plan against Lean reference calculations on a captured machine snapshot; two policies with the same first action but different later actions must exercise the horizon. Include an empty/invalid policy refusal according to the declared policy contract and a model revision mismatch.

**Locus/dependencies/risks.** Same new module as 6, with separate owned functions or sequential merges to avoid concurrent file edits. Depends on 7+8, supplies 6 and row 14; independent of C. Imagined state predictions are not U92's observed-state evidence. The FUNDAMENTALS signature redundantly mentions PolicyIndex as both an argument and kernel index; implement the all-policy kernel with per-policy evaluation, not two unrelated policy authorities (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:178`; `mathlib4/DarkTower/WarMachine/MachineQ.lean:84`).

**What it is.** Name the machine parameters it is uncertain about, and construct their distributions before and after a possible outcome under a policy. Verbatim: “Q(theta|pi) and Q(theta|o,pi) -- the parameter prior and posterior, and the theta they range over”; signature: `a declared machine Parameter carrier theta, plus ParameterPriorKernel PolicyIndex theta and ParameterPosteriorKernel PolicyIndex Obs theta constructed from the machine's model` (`futon2/holes/labs/wm-contract/FUNDAMENTALS.edn:293`).

**Current state.** Lean has both generic carriers (`mathlib4/DarkTower/WarMachine/Holes.lean:7026`; `mathlib4/DarkTower/WarMachine/Holes.lean:7030`), with witness-local parameter examples; no machine-bound theta constructor was resolved in the inspected declarations. Runtime EIG accepts prior/predicted observations/posteriors and validates their masses (`futon2/src/futon2/aif/epistemic_value.clj:64`); it is a consumer, not their producer. The existing a4a concentration producer counts capability×mission substrate pairs (`futon2/src/futon2/aif/a4a.clj:85`), explicitly the wrong target for live eq.21 (`futon2/holes/labs/wm-contract/aif-equations.edn:210`). State uncertainty, policy habit, capability beta scores and parameter uncertainty must not be renamed into each other.

**Acceptance (a), running construction.** Proposed `machine-parameters/parameter-kernels(model, parameter-state, policies, outcome-support)` constructs prior and posterior from the **same** declared machine likelihood and prior, including evidence normalizers and impossible-outcome status. Persist current parameter/model revision with the real tick snapshot; row 14's EIG integration calls `futon2/src/futon2/aif/epistemic_value.clj:64` only with 6's predictive outcomes and these compatible kernels. Posterior predictive Q must agree with the likelihood marginal if EIG's parameter model is used; independently authored Q/prior/posteriors are not acceptable.

**Acceptance (b), Lean statement.** Name theta and construct both normalized kernels at machine types; state Bayes conditioning and the positive-evidence premise, plus the marginal compatibility equation. Explicitly distinguish parameters of A/B/D from hidden states and policy priors. Current finite-support `ProbabilityKernel` (`mathlib4/DarkTower/WarMachine/Holes.lean:7015`) does not represent a continuous Dirichlet density merely because its concentration vector is normalized.

**Acceptance (c), production-match witness.** From a real parameter/model snapshot, compare every prior/posterior mass and evidence normalizer for two actual policies and informative/noninformative outcomes; include zero-evidence conditioning, support mismatch and an observation that changes the posterior. Compare EIG only after verifying the shared marginal Q. Record the next actual observed update separately from counterfactual posterior branches.

**Locus/dependencies/risks.** New `machine_parameters.clj` builds around the existing EIG consumer, not its binary-latent examples. Parallel interface/proof work is possible, but completed production matching depends on the shared theta/Outcome/likelihood contract and, for learned A/B/D, U91/U92. **Ambiguity requiring reviewer resolution within this packet's model contract:** the entry does not choose a parameter family. Narrow proposal: explicit finite support over registered machine-model parameter hypotheses, with their real likelihoods and an explicitly recorded prior; do not invent a workable/not-workable toy family. If the intended object is continuous Dirichlet parameter uncertainty, extend the mathematical probability representation and matching integrals instead—normalizing concentrations is only a predictive mean, not that posterior kernel. This note does not silently choose between those inequivalent targets (`mathlib4/DarkTower/WarMachine/Holes.lean:7026`; `mathlib4/DarkTower/WarMachine/Holes.lean:7030`; `futon2/src/futon2/aif/a4a.clj:85`; `futon2/holes/labs/wm-contract/aif-equations.edn:210`).

## Common acceptance evidence and dispatch boundaries

For every (c), use the F8 method: pinned real input capture → actual production function → retained Clojure readback → independently checked Lean reference values at identical source/model/support pins. Report per-coordinate deltas, raw outputs and refusals; `0.0` must be measured, never rounded into a pass. If floating evaluation differs, retain the difference and prove/declare the numerical error criterion under review; do not quietly expand a tolerance. Positive reference agreement and normalization **both** matter. A typed divergence demonstrates that the instrument can fail; it does not discharge a missing positive construction. No artificial fixture stands in for a machine instance. The adopted witness definition and limits are `futon2/holes/labs/wm-contract/TN-node-witness-carrier-proposal-2026-09-12.md:8`.

Each implementation packet must include all three legs and actual tick-consumer evidence, not merely new callable functions. Validate one relevant namespace at a time; run clj-kondo, check-parens and the relevant Lean witness plus its negative controls in an isolated test process, with the workspace's Lake authority rules. Integration tests must traverse the actual producer/consumer path with captured production inputs; transport can be stubbed, these constructors cannot. No live qualifying run, live-load from worktrees, or global status promotion is part of this discovery.

**What is scoped versus unresolved.** The six module responsibilities, integration anchors, dependency order and test obligations above are ready for assignment. Four semantic prerequisites still need explicit reviewed definitions, not implementation improvisation: entity/joint State; action-conditioned B and A→ruled Outcome; full evidence-outcome support; and theta/finite-versus-continuous parameter uncertainty. Item 5 mandates building them; it does not determine their probability laws. These are named model obligations for the packet owners/reviewer, not new purpose questions for Joe. Claiming that six wholly independent coding packets can complete without agreeing those definitions would conceal the principal discovery.
