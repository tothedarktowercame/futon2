# NOTE: pattern interpretations — pattern, production rule, proto-institution

Joe with zai-7 (zai), 2026-09-12. The breakdown the crew design was
hinting at: patterns have multiple interpretations, and different crew
roles consume different ones.

## The three interpretations

1. **Alexander-style design pattern** (the typical case): informal,
  flexible, "here is a recurring problem-context-solution shape."
  Interpretation-of-record for the library and the cartographer's map.
2. **Production rule**: condition → action, chainable. THE form the
  Workshop needs to author wiring diagrams — a wiring diagram IS a
  chained production system over chips (chips fire on conditions, wires
  carry the chaining). The interpretive step pattern → production rule
  is real work: it pins the pattern's flexible prose into guard/action
  form. It is the Workshop's core competence, and its errors are
  measurable (a mis-pinned rule fails its guard on real batches).
3. **Proto-institution**: pattern + preferences + DEONTIC aspect
  (permissions, obligations, prohibitions). The recent WM reading. An
  institution is a specification for HOW components may be wired —
  which combinings are permitted, obligated, forbidden.

## The key claim: an institution is itself a wiring diagram — a
## normative one

What happens in the Workshop is taking existing wiring components and
wiring them together; the institution provides the specification for
how to do that — and that specification has to come from somewhere, so
it is itself a wiring diagram of some kind. Not a mere production
system: a production system with a normative aspect. Concretely:

- a **board** is a wiring diagram (production system over chips);
- an **institution is a meta-board**: its chips are typed normative
  predicates over other boards (edge-permitted? chip-obligated-here?
  zap-forbidden-for-this-role?), and its wires chain the adjudication.
  The crew's existing constitutions ARE proto-institutions in this
  sense — "ZAP forbidden for the cartographer," "self-authored boards
  never self-ratify," "accepts-nothing, writes-no-ruling" are deontic
  annotations that already live in our specs as prose. The move is to
  make them first-class wiring.
- deontic annotations on EDGES, not just nodes: a wire may carry
  {:permitted-when ...} / {:obligated ...} / {:forbidden ...} with the
  same two-wire discipline — a forbidden traversal is a typed refusal,
  not an absence of wiring (C446 again, generalized).

## Circumstances of application — the question that motivated this

The Cascade Live map states design requirements; they could be rewritten
as patterns, but the goal is not more patterns — it is to know UNDER
WHICH CIRCUMSTANCES the requirements apply, since no artifact incurs all
of them. Alexander's own form already carries this ("context:" — the
pattern applies when), and the institution reading sharpens it into an
askable predicate:

- every requirement/institution carries an **applicability predicate**
  over the map and registry (which artifacts, which regions, which
  capability layers) — a query, per the askable-questions discipline;
- "does requirement R bind artifact A?" becomes a two-wire chip
  (FEEL-class), and an unaskable applicability is a named gap;
- applicability predicates are fresh-stamped like everything else: a
  binding verdict minted against an old map decays with map growth
  (same R14 idiom).

## Consequences for the roster

- Cartographer: interpretation 1 (map, associations, constellations).
- Workshop: interpretation 2 (production-rule pinning, wiring authoring
  at proposal precision) UNDER interpretation 3 (the institution
  constrains which wirings it may propose — the normative layer is the
  Workshop's own constitution, not its output alone).
- L4/WM: mints institutions (interpretation 3 is governance — Ostrom's
  collective-choice layer per M-G-over-cascades; editing it is the
  gated act).
- The pattern does not privilege one interpretation; the carrier stays
  the same, and which interpretation is "in force" is itself recorded —
  an interpretation is a lens with provenance, not a rewrite.
